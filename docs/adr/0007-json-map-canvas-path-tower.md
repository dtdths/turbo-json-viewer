# ADR-0007：JSON 地图 = Canvas 层级塔（v1.1）

- 状态：Accepted（范围 v1.1）
- 日期：2026-10-27
- 依据：用户新需求（节点过深时无法分辨层级/位置）；#17；`docs/design/json-map-spec.md`
- 相关：#6（视觉 token）、#9（选择语义）、#13（模块 seam）

## 背景

用户长期使用其他 JSON 工具时，深节点下不清楚「上一层是谁、当前 index、再上一级是什么」。
提出「JSON 地图」：类比 RTS/MOBA 小地图，用 Canvas 常驻显示当前节点的位置与层级。

讨论过：A 纵向层级塔；B 同心环；C 文档概览 + 当前路径。
用户看后选择 **A**（排除 B/C），v1.1 实施。

## 决策

1. **形态 = 纵向层级塔（A）**：根 → 当前节点逐层一行；显示 key、`[i/N]`、当前层相邻兄弟 key（前后各 2）。
2. **当前节点 = 选中行**；无选中时显示根节点。
3. **Canvas 绘制**，固定行高，DPR/主题适配；面板右下角约 260×220，可折叠。
4. **数据 = Worker 的 `getTrail`**（O(depth)），不遍历全文档、不建全量树；50MB 文档无额外扫描。
5. **交互**：点击祖先跳转/选中；点击兄弟选中；hover 完整 key/路径；无模式切换/拖拽/缩放。
6. **a11y**：Canvas 之外提供等价文本 breadcrumb + `aria-live` 路径播报。
7. **范围 v1.1**；不做 top-level 概览条、不做全文档压缩地图、不做同心环。

## 后果

- 直接解决深节点定位；实现小（Canvas 组件 + 一条 trail 协议），不影响 v1 主链路。
- 只显示祖先路径，不提供全局文档上下文；未来若需要，可在顶部加 C-lite 概览条（不在 v1.1）。
- 跟随选中行而非视口中心；用户若要「镜头框」语义需另立需求。

## 被否决的替代

| 方案 | 否决理由 |
|---|---|
| B 同心环 | 用户排除；标签阅读困难，深层更明显 |
| C 文档概览 + 当前路径 | 用户认为 A 已足够；C 需压缩/采样 2.96M 节点，成本高 |
| 纯 DOM breadcrumb | 无法直观表达层数与兄弟位置；Canvas 小地图是用户明确要求 |
