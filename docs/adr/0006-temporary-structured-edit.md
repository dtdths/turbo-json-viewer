# ADR-0006：临时结构化编辑（子树 JSON 编辑器，内存内、不改源文件）

- 状态：Accepted（方向；交互细节见 #16）
- 日期：2026-10-27
- 依据：用户需求（改 JSON 做 mock 数据，但**不修改原文件**；只做当前会话临时修改）；
  用户确认交互：**点击对象/数组 → 该值放入输入框 → 自行编辑 → parse 回去**；
  `docs/design/qa-editing-and-search.md`；#16。
- 相关票：#16（编辑 spec）、#7（IR/版本）、#9（操作语义）、#11（导出/原始视图）

## 背景

当前地图的 v1 定位是纯只读（编辑走外部工具）。用户日常用 bejson 的 textarea 改 mock 数据，
但明确：**不想改原始文件，只需要当前会话里的临时修改**。

讨论过三种编辑形态（见 `qa-editing-and-search.md`）：
A 纯只读；B 全文源文本编辑；C 子树/结构化编辑。
用户提出的「点节点 → 值进输入框 → 编辑 → parse 回去」就是 **C**，且它比「逐字段增删菜单」更简单：
一个通用的「子树 JSON 编辑」操作即可覆盖**标量改值、增删字段、增删子结构、键改名**。

## 决策

1. **v1 编辑 = 子树 JSON 编辑（唯一编辑入口）**：
   - 点击/右键任意节点 → 「编辑该节点 JSON」→ 弹层编辑器（CM6，行虚拟化）；
   - 编辑器内容 = `JSON.stringify(value, null, 2)`（当前值图，不是原始文本切片）；
   - Apply 时把文本 `JSON.parse` 回值，并**整段替换该节点**；标量、对象、数组、根节点同一套机制；
   - **不做**逐字段的「新增字段/删除字段/改键名」专用菜单——这些都在 JSON 文本里完成，
     避免每种操作各写一套 UI/撤销/路径分支。
2. **临时语义**：不写回源文件、不持久化文档内容；原文件与导入源文本保持不变；关闭页面即丢弃。
   - 撤销栈（深度 N，默认 100）、重置全部（重新 parse 源文本或反向撤销）、修改计数徽标；
   - 导出才写文件：导出当前值图的 JSON，文件名带 `-edited`。
3. **Mutation API**：主线程发 `{ t:'replaceNode', rootId, rootVersion, path, jsonText }`
   → Worker `JSON.parse(jsonText)`（大小受限）→ 替换该路径的值 → `rootVersion++`
   → 返回 `{ totalRows, changedRow, replacedNodes }`。**不重新解析整份文档、不重建全树。**
4. **行模型更新（结构变化）**：
   - Apply 后展开状态**已定（2026-10-27）：S1**——保留**被替换节点自身**的展开状态、其子节点默认折叠；
     S2（再保留替换后仍然存在的子路径的展开状态，需处理数组索引偏移）作为 v1.1 增强；S3（全折叠）不采用。
   - 若父容器已展开：重建该父容器 Fenwick（O(子项数)，193k 项约数 ms）+ 更新祖先可见行数；
     父容器折叠时只更新「共 N 项」与祖先计数（总行数不变）；
   - 清理被替换子树内的展开集合/选中/锚点；若替换发生在视口上方，按行高调整 `scrollTop`；
     主线程重取受影响窗口并高亮。
5. **守卫**：
   - 编辑器文本大小阈值（**5MB**；超阈值只读并提示「请选择更小的子树」；根节点同样受此限制）——已定（2026-10-27）；
   - JSON 语法错误：Worker 返回 line/column/消息，编辑器内显示，**不产生修改**；
   - 编辑值按 JS 语义（number 为 double）；大整数/精度、键序、重复键等已知保真限制要在 UI 提示；
   - 文本未变化（深度相等）→ no-op，不推进版本。
6. **与其它能力的一致性**：
   - 表达式结果根、搜索命中在结构修改后**标 stale / 清空**，由用户重新执行；
   - 复制/导出一律使用修改后的值图；
   - **原始文本视图**：始终显示原始源文本，修改后标注「原始文件文本，不含临时修改」；
     长期可选「按当前值图重建 pretty 文本」，但不在 v1。
7. **不做**：源文本/全文编辑（CM6 仅作为子树 JSON 编辑器和表达式输入；不再扩为 50MB 全文编辑器）、
   拖拽移动/重排、批量编辑、多文档合并。v1.1 再评估。
8. **原始文件永不写回**；浏览器也不会静默写本地文件，导出是唯一落盘动作。

## 后果

- 编辑能力从「逐操作结构化菜单」简化为**一个通用子树替换**：mutation 面小、UI 面小、撤销逻辑单一。
- 结构变化仍需认真处理行模型（Fenwick/展开集合/锚点），但都发生在用户显式 Apply 时，可接受一次性毫秒级成本。
- 被替换节点折叠会让「改完看不到内部」；可用展开 + 高亮缓解（#16 可再定「保留原展开路径」）。
- 大子树编辑受阈值限制；50MB 全文档编辑不可行，但用户可以编辑其子结构或导出后用外部工具改整份。
- 原始文本视图与值图分歧成为常态（尤其新增字段）；必须显式标注，避免用户误判。
- 子树 JSON 编辑使用 **CM6 + `@codemirror/lang-json`**（JSON 语法高亮 + lint）——已定（2026-10-27，+少量 gz 待实现时实测）。

## 被否决的替代

| 方案 | 否决理由 |
|---|---|
| 逐字段「新增/删除/改名」菜单（上一轮的方向） | 每种操作各有一套 UI/撤销/路径逻辑；同样能力用「编辑子树 JSON」一个操作即可覆盖 |
| CM6 全文源文本编辑 | 用户不需要；整份文本编辑的阈值/双源问题更重；子树编辑已覆盖 mock 工作流 |
| 保持纯只读（编辑走外部工具） | 用户明确需要会话内改 mock 数据 |
| 写回原文件 | 用户明确不想改原文件；浏览器无法静默写回本地文件 |
