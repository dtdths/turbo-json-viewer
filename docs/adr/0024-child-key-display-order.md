# ADR-0024：子键显示排序（对象成员的显示顺序）

- 状态：**Accepted（设计定稿 2026-11-12；实现完成 2026-11-12，见 #40 验收）**
- 日期：2026-11-12
- 依据：`#19`（想法票：节点子键按规则排序）；2026-11-12 grill 一轮拍板 Q1–Q8（全部按推荐）；实现票 #40
- 相关：#19（本 ADR 的设计来源）、#1（地图）、ADR-0002（行模型 / Fenwick / 展开集合）、ADR-0013 §2（大纲键序 = 值图顺序——本 ADR 修订为「跟随显示排序」）、ADR-0011（设置面板 / 持久化）、ADR-0022（设置项记账先例）、ADR-0023（相邻 slice 的验收记账格式）
- 术语：`CONTEXT.md` 新增 **显示顺序（Display Order）**、**子键排序（Child Key Sorting）**

## 背景

一个节点下成员很多时（`{"k0001": …, "k0002": …}`），键序是插入序，用户无法一眼找到目标键。现状事实（2026-11-12 实测，HEAD `13a43aa`）：

- **键序是产品承诺**：`CONTEXT.md:12` 明确「对象的成员键序需保持」，`docs/design/reassess-fidelity.md` 实测键序保真 0 风险；#23 还把「整数样式键被 JS 重排」当作**失真**在报。→ 排序只能是**显示顺序**，绝不能改值图。
- **行序来源单一**：`RowModel.keysOf(container)`（`src/core/row-model.ts:730`）= `Object.keys` + `WeakMap` 缓存；`slot` 即键序。行窗口（`RowWindow.rows`）在 **Worker** 物化，主线程只取窗口。
- **路径与身份与 slot 无关**：`shared/path` 的 `appendKey` / `appendIndex` 按**键**拼路径；复制 / 导出 / 编辑 / 搜索 / 保真全部按值图与路径工作，不读 slot。→ 只改 slot 顺序，天然不影响这些语义。
- **版本口径**：`rowVersion` 是行映射的**唯一失效令牌**（`doc-service.window` 校验，不符即 `STALE_ROOT`）；页面 `WindowMachine` 对 `STALE_*` 自动重取（上限 3）。排序变化只是一次行映射变化，**不需要新增 orderVersion 字段**。
- **大纲是第二条键序出口**：`src/core/outline.ts:55` 直接 `Object.keys`，ADR-0013 §2 写明「不做显示排序（#19 待拍板）」——本 ADR 必须一并裁决。
- **表达式结果树同一渲染器**：`expr:N` 根也走 `RowModel` + 同一 `rowSource`（`main.ts:718`）。
- **设置基础设施已就绪**：`SettingsPanel` 12 行、`SettingsState` 白名单归一化、`tjv.settings.v1` 持久化、`settings.subscribe → applySettings()` 即时生效；设置面板在左面板，**打开时树区仍可见**（能即时看到重排效果）。
- **预算顶格**：`page.js` **49.0KB gz / 预算 50**（余 1.0）；排序逻辑放 `core`（→ worker bundle，无 page 预算压力），page 侧只增一个设置键 + 一行 DOM。

## 决策

### 1. 语义：显示顺序（view-only），不是数据重排

- `RowModel` 增加「容器 → 显示键序」的覆盖层：`keysOf` 返回**显示顺序**的键数组，slot / Fenwick / 行窗口全部随之；**值图、键序承诺、路径、节点身份、复制、导出、编辑、搜索、保真全部不变**。
- ADR 措辞：**显示顺序是根级视图状态**（与展开集合同类），随文档会话存在，不进值图、不落盘（顺序规则本身进设置持久化，见 §3）。
- 因此「复制 / 导出 / 编辑回填 / 搜索结果顺序 / 原文视图」都保持原语义——这是本决策的直接收益，无需逐处改代码。

### 2. 作用范围：只排对象成员，数组保持索引序

- 数组元素顺序有语义，`[i]` 路径依赖索引；排数组要连带改路径口径，收益低、风险高。v1 明确不做。

### 3. 控制面：全局统一设置 + 三档规则

- **命名对应**：协议/代码用 `SortOrder`（= 设置项 `sortOrder` 的取值），对应 CONTEXT 的**概念**「显示顺序」与**设置**「子键排序」；算法单一入口在 `core/order.ts`。不额外引入 `DisplayOrder` 第二套叫法（一处概念两个名字反而更容易漂移）。

- 规则三档：**原始顺序（默认）** / **键名升序** / **键名降序**。默认「原始顺序」= 行为与今天完全一致。
- **自然序比较器**（自研、确定性）：
  - 数字段按**数值**比较（`item2 < item10`；前导零由数值比较吸收）；
  - 非数字段**忽略大小写**比较；
  - 全部平局时用**原码元序**兜底（保证是全序、结果与平台无关）；
  - **不用** `Intl.Collator` / `localeCompare`：ICU 版本漂移会让不同 Chrome 版本 / 单测结果不一致。
- 中文 / 非 ASCII 键按**码元序**（不做拼音、不做 locale 排序）——写进已知差距。
- 入口：**设置面板第 13 行**（segmented：原始 / 升序 / 降序），随 `tjv.settings.v1` 持久化；不做树区下拉、不做工具栏按钮（避免两个入口两个真相源）。
- v1 **无单节点覆盖**（每节点单独排 / 右键菜单）→ v1.1。

### 4. 生效范围：树 + 大纲 + 表达式结果树跟随；其余不跟

- **跟随**：树行序、**大纲面板**子项序（ADR-0013 §2 相应修订）、**表达式结果树**（同一渲染器 + 同一规则，一致性优先）。
- **不跟**：搜索结果列表（保持命中 / walk 序）、原文视图（原文顺序即原文）、复制 / 导出 / 编辑回填 / 表达式补全列表（`complete` 的根字段提示仍是值图序）。
- 大纲的分页按**显示序**切页；`total` 不变。

### 5. 切换排序后的视图动作：按路径保持锚点

- 切换前记录**视口顶端可见行的规范路径**；切换后询问该路径的新行号并把视口滚回该节点（保留行内像素偏移）；不可见则回顶部。
- **选中节点按路径保留**（路径与身份与 slot 无关，选中态天然不受影响）。
- **搜索不重跑**：命中集与 `Hit.field` 不变；树行高亮本来就按 `row.path` 匹配（`tree-view.ts:266`），重排后自动正确。
- 大纲若正开着 → 刷新当前页。

### 6. 实现载体

- **`core/order.ts`（新建）**：`SortOrder`、白名单归一化、自然序比较器、`orderedKeys(container, order)`。
- **`RowModel`**：`order` 进构造选项；`keysOf` 走显示序并在 `keysCache` 缓存（**首次需要该容器键序时才排序 + 缓存** = 懒排序，成本不进导入首帧）；`setOrder(order)` 重置键缓存并按新 slot 序**重建 `expanded` 集合里每个容器的 Fenwick**。
  - 关键不变量：**子树可见行数（Fenwick 总和）与顺序无关**，所以每个展开容器可独立重建 sizes（按新序 `measureChildren`），无需自底向上遍历整棵值图。
- **`doc-service`**：服务级 `order`（根创建时套用到 `RowModel`——doc 根与 `expr:` 根都套）；新命令 `setOrder { order }` 对**全部活根**生效并各推 `rowVersion++`，回包给每个根的新版本快照（页面按 rootId 回填标签会话 / 表达式视图坐标）。
- **新命令 `rowOfPath { rootId, path }`（只读）**：路径 → 可见行号（不可见 −1），供切换后的锚点换算。不推任何版本。
- **`protocol`**：`Command` 两条 + `CoreApi` 两个方法 + 双适配器契约（InProcess / Worker）。
- **页面**：`settings-state` 新增 `sortOrder`；`settings-panel` 13 行；`main.applySettings` 检测规则变化 → `core.setOrder` → 回填全部标签 / 表达式根的 `rowVersion`/`totalRows` → 重取活动根窗口 → 按路径还原锚点；`WindowMachine` 对切换瞬间的 `STALE_ROOT` 自动重取。

### 7. 性能与护栏

- **懒排序**：容器键序在首次被需要（窗口 / 展开 / 大纲页）时才排序并缓存；导入首帧零排序成本。
- **切换成本**：O(展开容器子项总数) 的一次 Fenwick 重建（≈ 可见行数）；worker 内完成，主线程只等一次窗口回包。
- **不设硬上限**：用 50MB 样本实测「单容器超大键数」的首次展开 / 切换成本；只有实测不可接受时才增加「该容器保持原始序 + 一次性提示」的兜底（届时另记 ADR 修订，不在本轮预先拍死）。
- **实测（2026-11-12，Chrome for Testing 156 / dev 构建）**：
  - 合成**单对象 20 万键**（2.4MB，Q7 的目标风险形态）：load（含首窗排序）**119ms**；切 asc **54ms** / 切 desc **53ms**（wall，含 worker 内 20 万键自然序排序 + Fenwick 重建 + 窗口重取）；测量窗口内仅 1 次 60ms 长任务（发生在 load 阶段，非切档）。
  - **50MB 真实样本**（`items` 是大数组、对象容器都很小）：切档 wall **27ms**、**0 长任务**。
  - 结论：本口径下无需硬上限（20 万键切档 ≈54ms，worker 内完成、主线程不卡）；若将来出现「几十万键 × 每次切档」的真实抱怨，再按 §7 兜底并另记修订。

## 被否决的替代

| 方案 | 否决理由 |
|---|---|
| 真实重排值图（改 `JSON.parse` 结果的键序） | 违背「成员键序需保持」的产品承诺；复制 / 导出 / 编辑 / 路径 / 保真全部连带变化，且不可逆 |
| 数组也按规则排 | 数组顺序有语义、`[i]` 路径依赖索引；收益低、路径口径风险高 |
| `Intl.Collator` / `localeCompare` 排序 | ICU 版本漂移 → 不同 Chrome / 单测结果不一致；自然序自研更可控 |
| 树区顶部或工具栏再放下拉 | 与设置面板形成两个入口两个真相源；额外 UI/预算成本 |
| 单节点覆盖（全局默认 + 每节点排序） | v1 复杂度与交互面（右键菜单 / 状态持久化）不划算；明确留 v1.1 |
| 大纲保持值图序（不跟随） | 同一文档的两条层级导航面顺序不一致，看起来像 bug；大纲本就要随 #19 另议（ADR-0013 §2 已预留） |
| 搜索结果列表也按规则排 | 搜索结果是「命中集合」，其价值在命中序 / 文档序；重排会破坏「上下条」导航语义 |
| 新增 `orderVersion` 独立版本字段 | `rowVersion` 本就是行映射失效令牌，排序变化就是一次行映射变化；多一个版本字段只会制造第二条失效路径 |
| 切换排序时回顶部 / 保持原行号 | 回顶部丢上下文；保持行号会跳到完全不同的节点（顺序变了行号含义变了）——按路径锚点才是「保持你正在看的东西」 |
| 导入 / 加载时对所有容器预排序 | 把成本压进首帧（50MB / 3M 节点），与「极速首帧」卖点冲突；懒排序即可 |
| 改 `frameOf` / `countAllExpandedRows` 全量走显示序 | 这两处只用于计数与全展开重建，顺序无关；只有 Fenwick sizes 数组需要对齐 slot 序 |

## 已知差距 / 本轮不做

- **中文 / 非 ASCII 键按码元序**（非拼音、非 locale 排序）。
- **数组不排**；只排对象成员。
- **无单节点覆盖**、无「按类型 / 按值 / 按项数」排序（v1.1）。
- **表达式补全列表仍按值图序**（`complete` 的根字段提示不做显示排序）。
- **折叠容器的行摘要预览仍按值图键序**（`summarizeContainer` 取前 N 个成员做预览串——它是「预览采样」而不是行，本轮不改 `previewOf` 签名；展开后才是显示序）。
- **大纲「加载更多」每页重新枚举 + 排序**该容器键（ADR-0013 的「不缓存」口径不变）——超大容器分页时每页多一次 O(n log n) 排序，待实测。
- **保真报告不受影响**：整数样式键被 JS 重排的失真照报（显示序可能掩盖「原始顺序」下的键序问题，但报告口径不变）。
- **无排序状态指示**：树区不显示「当前按升序」角标（设置面板里的 segmented 回显即唯一入口）。
- 大容器**不设硬上限**（见 §7）：20 万键单容器切档实测 ≈54ms、50MB 样本 ≈27ms / 0 长任务，暂不需要兜底。

## 决策来源（2026-11-12 会话，grill 一轮 8 问，全部按推荐）

- **Q1 语义** = 显示顺序（view-only）；值图 / 路径 / 复制 / 导出 / 编辑 / 搜索不变。
- **Q2 范围** = 只排对象成员，数组保持索引序。
- **Q3 规则集** = 原始 / 键名升序 / 键名降序；自然序自研比较器（数字段数值、忽略大小写、平局码元序），不用 `Intl.Collator`；中文按码元序。
- **Q4 控制面** = 全局统一设置，设置面板第 13 行，持久化 `tjv.settings.v1`，默认原始顺序；单节点覆盖留 v1.1。
- **Q5 生效范围** = 树 + 大纲 + 表达式结果树跟随；搜索结果 / 原文 / 复制 / 导出 / 编辑 / 补全不跟；需 ADR-0013 §2 修订指针。
- **Q6 切换动作** = 按路径保持锚点；选中按路径保留；搜索不重跑（高亮按 path 天然正确）。
- **Q7 大容器** = 懒排序（首次需要键序时）+ 缓存；不设硬上限，50MB 实测后按需兜底。
- **Q8 记录方式** = 新开 ADR-0024；排序逻辑进 core/worker 不动 page 预算；验收含 16 套冒烟 + `--analyze` + 截图，page >50 带数字找用户批。
