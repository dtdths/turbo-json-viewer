# ADR-0027：表达式结果的原文档路径可见 —— 以及「多条件搜索走表达式」的取舍

- 状态：**Implemented**（2026-11-18；实现票 #49）
- 日期：2026-11-18
- 依据：ADR-0018（表达式视图 / `origins` 只在 worker）、ADR-0023（「搜到的 == 看到的」）、#47（需求批次拍板汇总）
- 相关票：#47（批次）、#49（本 ADR 的实现票）、#53（搜索增强）

## 背景

1. **表达式结果行只有「结果坐标」**：结果根 `expr:N` 的行路径是 `$[3]`、`$[3].name` 这种结果内坐标。用户 `filter` 出一批记录后，看不出它对应原文档哪里——点行能跳回去（`exprLocate`，ADR-0018 §4），但**看不见**。多条件筛选走表达式之后，这个缺口会从「锦上添花」变成「功能不可用」。
2. **用户提「多条件搜索」**（例：`key = "errorcode"` 且 `value = "500"`，取交集/并集）。现成能力是「单查询 + 四档 field 过滤」（`all/key/value/path` 是对单条查询结果的二次过滤）；而表达式白名单已有 `filter/some/every/find/includes/startsWith/toLowerCase/Math.*` 等，任意条件本来就能表达。

## 决策

### 1. 表达式结果行**随行窗口回带**原文档路径（不新建映射、不做页面侧索引）

- 协议：`Row.originPath?: Path | null` —— **只有 `kind === 'expression'` 根的行带这个字段**（doc / repaired 根不出现）；「字段是否存在」就是「这是表达式结果」的判据。
- worker：`DocService.window` 组装回包时，逐行 `locateOriginalPath(root.value, root.expr.origins, row.path)`（ADR-0018 §4 的**最深已知容器 + 相对后缀**启发式）。来源映射是 worker 内的 `WeakMap`，**永不跨线程**；页面不自算（ADR-0018 已否决页面侧全量路径表）。
- `null` = **计算值**：`map(x => ({ id: x.id }))` 这类产出的新对象没有文档身份，不假装有来源。
- 成本：每窗口 ~30 行 × O(路径深度)，实测可忽略（无长任务，`smoke-expression` 的 longtask 断言保持 0）。

### 2. 展示口径

| 位置 | 行为 |
| --- | --- |
| 状态栏 `#statusPath` | 表达式视图下并列：`$[3].name ← $.data.items[2].name`；计算值 → `$[3].name ← 计算值（无原文档路径）` |
| 表达式结果树键名 `title` | hover 显示**原文档路径**（计算值显示「计算值」）；doc 树 hover 显示该行规范路径 |
| 右键菜单 | 新增「复制原文档路径」（仅表达式结果可用；计算值禁用并说明原因）；**「复制路径」语义不变**（仍是结果坐标），避免破坏既有复制契约与冒烟 |

### 3. 多条件搜索：**不做自研**，表达式面板即入口

- 不新增搜索协议、不做条件行 UI、不做查询语法（后者的解析歧义与面板预算都不划算）；
- 表达式面板把首个数组字段的 `.slice(0, 5)` 示例**替换**成 `filter(...)` 示例（示例总数仍是 5：3 动态 + 2 通用）+ 一行多条件筛选引导文案；
- **已知差距**：表达式不支持正则字面量（ADR-0018 §3 的 `RegExpLiteral` 拒绝，保留「无正则 → 无 ReDoS 面」）；模糊匹配用 `includes/startsWith/toLowerCase` 组合。

## 后果

- 表达式结果从「只有结果坐标」变成「可读、可复制、可 hover 查看的原文锚点」；多条件筛选路线才真正闭环。
- **不追求逐节点精确**：映射是「最深已知容器 + 相对后缀」启发式，计算值显式为 `null`；同一节点在结果里出现两次时，两行映射到同一原路径（接受）。
- `originPath` 只出现在表达式的行窗口里，doc 根的行负载不增加（首屏路径零成本）。

## 被否决的替代

| 方案 | 否决理由 |
| --- | --- |
| 页面侧全量 path→origin 表 | ADR-0018 已否决（50MB ≈ 10MB 级表） |
| hover 时逐行调 `exprLocate` | 每行一次 worker 往返 + tooltip 时序不稳；随窗口回带的成本可忽略 |
| 自研条件行 UI / 查询语法 | 解析歧义（值里带冒号、路径带空格）+ 面板预算；表达式已覆盖且历史可复用 |
| 为表达式放开正则字面量 | 重新打开 ReDoS 面（ADR-0018 明确拒绝） |

## 审查收口（2026-11-18，双轴 review 后）

首版实现（`fe404fa`）被双轴审查抓出三个真缺陷，已修：

1. **标量结果根被误标「计算值」**：`locateOriginalPath` 的候选只有「对象身份」与「第一段子项来源」，标量结果根
   （`$.data.name`、`$.data.items[0]`）两边都覆盖不到 → `EvalOrigins` 增加 **`root`**（= 求值结果自己的 `Ev.p`），
   `segments.length === 0` 时直接返回它。`$` 行不再误报「计算值」，菜单也不再误禁用。
2. **状态栏原路径随滚动丢失**：`WindowSnapshot.rows` 只是视口 ± overscan 的窗口，选中行滚出窗口后 `find` miss，
   状态栏会从「$[3] ← $.data.items[2]」退回「$[3]」。新增**选中行原路径缓存**（`setSelection` 与每个窗口帧刷新；
   换根 / 离开表达式视图 / 清选中时失效），缓存值仍只来自 worker 回包，页面不自算映射。
3. **toast 双重「复制」**：「已复制：复制原文档路径」→ 新增名词词条 `app.copy.format.originPath`（「原文档路径」），
   与四格式复制同口径。

顺手项：隐藏行池槽位清 `keyEl.title`（池复用纪律）；`smoke-expression` 拆开「键名 title」与「筛选示例」断言、
