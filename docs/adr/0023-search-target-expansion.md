# ADR-0023：搜索目标扩展（布尔/null 值命中 + 路径后缀命中）

- 状态：**Accepted（设计定稿 2026-11-12；实现待 #39）**
- 日期：2026-11-12
- 依据：`#36`（#10 收口残余项：布尔/null 值、路径片段搜索）；2026-11-12 grill 两轮拍板（Q1–Q9，全部按推荐）
- 相关：#36（设计票）、#39（实现票）、ADR-0014（搜索语义：匹配目标 / Aa / 正则 / 上限）、ADR-0010 §2（规范路径）、ADR-0013 / ADR-0019（规范路径 = 节点身份）、ADR-0002 修订（行模型）、ADR-0011（设置不扩）
- 术语：`CONTEXT.md`（搜索 / 路径（规范路径）/ 值 / 命中）；本 ADR 新增两个词：**路径模式**（查询含 `.` / `[` / `$` 时启用路径命中）、**路径命中**（`field='path'` 的命中）

## 背景

- 现状（2026-11-12 实测，HEAD `a0e098c`）：搜索命中目标 = **键名 + 值**；值 = 字符串内容 + 数字的**显示文本**（number → `JSON.stringify`、BigInt → 十进制串，ADR-0014 修订）；**布尔/null 不参与**。`Hit.field` 只有 `'key' | 'value'`；结果面板过滤三档「全部 / 键名 / 值」。
- 搜索是全量 walk（`core/search.ts`），无索引；命中上限 `SEARCH_LIMIT=50,000`，超出截断。walk 的栈帧**逐节点已带规范路径**（`frame.path`，由 `shared/path` 的 `appendKey` / `appendIndex` 增量拼接），路径命中不引入新索引或额外遍历。
- 规范路径（ADR-0010 §2）形态：根 `$`；标识符键 `.key`；非标识符键 `['a.b']`；数组元素 `[i]`。例：`$.data.hotel_list[3]`。
- 历史：#10 的讨论轮曾拍「搜索目标 = 键名 + 值 + 路径」，slice 4 收窄为键名 + 字符串值，路径搜索留在票内（ADR-0014 §2.1 明确「路径不参与」并对齐该现状）。数字值被用户实际使用否决后（ADR-0014 2026-11-12 修订），同理暴露出：树里看得见的 `true` / `false` / `null` 搜不到；`hotel_list[3]`、`$.data` 这类路径文本搜不到。

## 决策

### 1. 布尔/null 值命中（`field='value'`）

- `searchableValueText` 扩展：`boolean` → `'true'` / `'false'`，`null` → `'null'`（与 `row-model.scalarPreview` 同源，保证「搜到的 == 看到的」）。
- 匹配语义与字符串/数字**完全一致**：子串、大小写按 `Aa`、正则模式同规则；`keysOnly=true` 时仍只搜键名（值/路径都不收）。
- 噪声接受：与数字值同口径（搜 `t`/`ul` 会命中大量布尔/null），由 50,000 上限与结果过滤兜底；**不做**全词/精确匹配特例。

### 2. 路径命中（`field='path'`）：仅路径模式 + 后缀匹配

- **路径模式触发**：查询串包含 `.`、`[` 或 `$` 之一时，才收集路径命中；普通词查询**完全不碰**路径（零噪声、零额外比较）。
- **匹配语义 = 规范路径后缀匹配**：
  - 字面量模式：`path` 以查询串**结尾**（大小写按 `Aa`）；
  - 正则模式：对**整条规范路径** `test()`（用户可自行用 `$` 锚定后缀）；
  - 不做任意中段子串匹配（与 grill Q8 的修正一致）。
- 例：`$.data` → 只命中节点 `$.data`；`hotel_list[3]` → 命中该节点；`items[3]` / `[3]` → 命中所有路径以该后缀结尾的节点（各数组的第 4 个元素）；`$` → 只命中根；`data.` / `.` → 0 条（没有路径以它们结尾，**不会**命中整棵子树）。
- 匹配目标是 walk 帧上已有的规范路径字符串：无新索引、无额外路径构建；路径模式下每节点只多一次 `endsWith`（或正则 `test`）。
- 根节点路径为 `$`；数组元素键名为 `[i]`。路径命中与 `rootId` 无关，对当前搜索根（含表达式结果根）同样生效。

### 3. 命中模型：一节点一条，优先级 key > value > path

- 沿用既有不变量：一个节点最多产生一条命中；`field` 按 **key > value > path** 只记一个（路径只在键名、值都没命中时记录）。
- `keysOnly=true` 时不收集路径命中（该选项语义 = 只搜键名）。
- 过滤计数和 = 命中总数（`all = key + value + path` 的既有假设不强制，但计数从同一 `allHits` 重算）。

### 4. UI：过滤四档常驻 + 结果行文案

- 结果面板过滤从三档扩为**四档常驻**：全部 / 键名 / 值 / **路径**，各带计数；普通查询下「路径」计数为 0（与其他档 0 命中一致：可点、空列表，不 disable）。
- 结果行：`field` 文案增加「路径」；路径列（面包屑）沿用现有 `writeHighlighted(pathEl, hit.path, term)`，自然高亮命中后缀；值列 / 类型列 / 单击跳转 / 双击复制 / 树行 `.is-hit` 高亮**均不变**。
- 查询框 `placeholder` / `aria-label` / 空态文案改为「搜索键名、值或路径…」。

### 5. 上限 / 性能 / 持久化不变

- 命中上限仍是全局 `SEARCH_LIMIT=50,000`、超限 `truncated`；不新增每字段上限。
- 无搜索索引（#10 已否决：50MB 索引成本不划算）；路径模式不改变遍历方式。
- 过滤档位仍是**会话态**、不进设置（ADR-0011 口径不变）；`Aa` / `.*` 语义不变。
- 不新增协议命令、不新增 Worker 结构；只扩 `Hit.field` 的联合类型与 UI。

### 6. 分层

- `core/search.ts`：匹配目标（bool/null）+ 路径模式 + 后缀匹配 + `field='path'`；`protocol/types.ts`：`Hit.field` 联合加 `'path'`；`viewmodel/search-state.ts`：`SearchFilter` / `SearchCounts` / 过滤与计数；`view/panels/search-panel.ts`：第四档、文案、行内 field 文案。
- 独立参考实现 `tests/unit/core/search-reference.ts` 同步新语义（parity 矩阵），冒烟 `smoke-search` / `smoke-extension-search` 增加真机断言。

## 被否决的替代

| 方案 | 否决理由 |
|---|---|
| 路径命中用任意子串匹配（Q8=(a)） | `data.` 会命中 `$.data` 整棵子树的所有后代，结果洪水并挤占键名/值命中；与「按路径找节点」的心智不符 |
| 路径子串 + 路径档独立上限（Q8=(c)） | 洪水仍在，只是换截断位置；协议 / 计数 / UI 都要扩，收益不抵复杂度 |
| 路径命中始终启用（不要求 `.`/`[`/`$`） | 普通词查询（如 `data`）会产生大量嘈杂路径命中，且对普通搜索毫无用处 |
| 每字段各产生一条命中（Q5=(b)） | 同节点多行、列表不再以节点为中心，filter 计数和 ≠ 命中总数，与既有不变量冲突 |
| 布尔/null 全词/精确匹配（Q6 特例） | 与「值 = 显示文本子串」的既有定义冲突，同一 filter 下规则随类型变化，难解释 |
| 正则模式也给路径加后缀约束 | 给正则附加锚点语义、解释成本高；改为对整条路径 `test()`，由用户自己用 `$` 锚定 |
| JSONPath / 通配符 / 查询语法 | 超出「搜索」心智，属表达式视图（ADR-0018）领域；本 ADR 只做路径文本后缀 |
| 建路径索引 / 预计算路径表 | 50MB 成本不划算（#10 已否决）；walk 帧已带路径，后缀匹配不需要索引 |
| 每次搜索都问用户「搜路径吗」/ 设置项 | 交互成本高；路径模式由查询形态自然触发，无需新入口或新设置 |

## 验收（待 #39 实现后补实测）

- **单测**：`core/search` 的 bool/null 命中（含大小写 / 正则 / keysOnly 不收）+ 路径模式触发规则 + 后缀匹配例表（`$.data` / `hotel_list[3]` / `[3]` / `$` / `data.` 0 条）+ 一节点一条与 key > value > path 优先级 + 截断；独立参考实现 parity 矩阵扩展；`protocol` 若有 `Hit` 形状契约同步。
- **冒烟**：`smoke-search` 增加布尔/null 命中、路径命中（导航/树高亮/双击复制）、filter 四档计数、`data.` 0 条、路径模式 0 长任务；`smoke-extension-search` 同步；两套计数如实增加（其余套件不变）。
- **体积**：`page.js` 从 48.9/50 记账（超预算先问用户）；`worker.js` 无硬预算（ADR-0020 §9 起记录）。

## 已知差距 / 本轮不做

- 路径只支持**尾部片段**；中段/前缀查询不命中（`data.` → 0 条是有意行为）。若出现真实的中段需求，另开票评估。
- 正则模式下路径命中不做后缀约束（对整条路径 `test()`），宽正则（如 `data`）会命中大量节点，由 50,000 上限 / 截断兜底——与正则本身的「用户自负」口径一致。
- 不做「类型搜索」（如只搜 boolean）、不做搜索目标设置项 / 每次搜索的临时开关。
- 布尔/null 只有值命中（无键名概念）；大小写不敏感时 `True` 命中 `true`，与字符串一致。
- 无「路径命中优先排序」——结果仍按 walk（文档前序）顺序；排序/分组不在本票。
- 表达式结果根的路径来自结果根（非原文档路径），不特殊处理；由现有 exprLocate 负责跳回原文档。

## 决策来源（2026-11-12 会话，grill 两轮）

- Q1 布尔/null 值 = 纳入，按显示文本子串（与数字同口径）；Q2 路径命中 = 做，规范路径文本、不做 JSONPath；Q3 本轮只做设计（ADR + 实现票）；Q4 路径仅在查询含 `.`/`[`/`$` 时启用（普通查询零成本零噪声）；Q5 一节点一条命中，优先级 key > value > path；Q6 布尔/null 用子串、不做特例；Q7 布尔/null 与路径合成一张实现票；Q8 路径语义**修正为后缀匹配**（Q2 原「子串」口径在边界推演中发现 `data.` 子树洪水，故收紧）；Q9 过滤四档常驻（路径 0 命中时与其他档一致，可点空列表）。
