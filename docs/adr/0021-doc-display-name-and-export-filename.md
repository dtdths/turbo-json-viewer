# ADR-0021：文档显示名 ↔ 导出文件名 —— 一个名字、系统「另存为」、双向联动

- 状态：**Implemented**（2026-11-12；设计拍板 2026-11-12 会话，见「决策来源」）
- 日期：2026-11-12
- 依据：用户 2026-11-11 需求「希望可以自定义标签名 / 文件名」（#29）；2026-11-12 grill 逐轮拍板
- 相关：#29（本 ADR 的票）、#35（最近文档；显示名持久化留待该票）、ADR-0004 §7 / ADR-0006 §2（`-truncated-repaired` / `-edited` 后缀）、ADR-0009（多文档工作区 / 标签条）、ADR-0012（导出分体按钮）、ADR-0018 §4（表达式结果导出名）、ADR-0020（无损序列化）

## 背景

- 标签条标题 = 导入文件名（`meta.name`：来自 `File.name` 或粘贴默认名 `剪贴板.json`），**不可改**；导出文件名 = `exportName(meta.name, edited, repaired)` 派生（`<原名>[-truncated-repaired][-edited].json`）；表达式结果导出 = `<原名>-expr-N.json`。
- 用户 2026-11-11 提出希望自定义标签名 / 文件名（#29），2026-11-12 grill 拍板：**一个名字同时管标签显示与导出基名**，导出改为**系统「另存为」**（可改名字 + 选保存位置），保存后按最终文件名**反推**回标签名（双向联动）。
- 现状的导出是 `<a download>` 直落默认下载目录：名字只能靠后缀派生、无法选位置；单文档时标签条隐藏，改名没有任何入口。

## 决策

### 1. 一个名字，两处显示（每标签独立，会话内有效）

- **显示名 = `TabState.name`**，默认等于导入文件名；`meta.name` 保留**原名只读**（不参与导出，只用于悬停提示「原名：…」追溯）。
- 显示名同时是**导出基名**：导出文件名 = `<显示名>[-truncated-repaired][-edited].json`（后缀顺序与旧 `exportName` 逐字节一致，ADR-0004 §7 / ADR-0006 §2）。表达式结果导出 = `<显示名>-expr-N.json`（ADR-0018 §4，同样受 120 上限约束）。
- 作用域：**每标签独立**，不做工作区级默认命名偏好；**会话内有效、不落盘**（与 ADR-0009 §4「标签本身不落盘」一致），#35 最近文档再议恢复。
- 改名**不算修改**：不置「已修改 N 处」、不影响 `-edited` 后缀、不进编辑历史 / ⌘Z、关标签不额外确认。

### 2. 文件导出 = 系统「另存为」（File System Access API）

- 文件导出走 `window.showSaveFilePicker`：预填默认名（含本次后缀）、用户可改名字 / 选保存位置、系统框确认后才写入；**取消 = 不导出、不改名、零副作用**。
- **无 FSA 时回落** `<a download>`（用当前默认名直落下载目录，无确认框——如实记录为已知差距）；**API 存在但被环境/企业策略拒绝**（非 `AbortError`）同样回落普通下载、导出不中断。
- **不新增 `downloads` 权限**（零权限纪律：`chrome.downloads` + `saveAs:true` 会多一条「管理你的下载」安装警告，否决）。
- **不做「记住上次导出目录」**：需要 `showDirectoryPicker` + IndexedDB 目录句柄 + 权限生命周期，另开票再议（见「被否决的替代」）。
- 「复制 JSON 到剪贴板」不变：无文件名、不弹框（ADR-0012 §2）。

### 3. 双向联动

- 标签改名（多标签就地编辑）→ 下次导出的预填名跟着变（预填 = 当前显示名 + 本次后缀）。
- 保存后**最终文件名 ≠ 预填名** → 反推基名写回标签：剥 `.json`（大小写不敏感）→ 按**本次确实加过**的 flags 剥后缀（先 `-edited` 再 `-truncated-repaired`）；清洗后为空则不动（`renameFromExport`）。
- **表达式结果视图的导出是一次性文件名**：可整名编辑（含 `-expr-N`），保存后**不回写**文档名——结果根是派生视图，不应反写文档身份。
- 保存过程中切标签不会串味：文件名与目标标签 id 都在 `await` 前定死（沿用旧的「名字必须在 await 前定」纪律）。

### 4. 改名入口

- **多标签（标签条可见时）**：双击标签标题进入就地编辑；**F2** 是键盘等价入口；**Enter / 失焦提交、Esc 取消**；编辑期间标签 `draggable=false`（不与拖拽排序抢手势）；提交后标签、文件 chip、悬停 title 同步。
- **单标签**：标签条隐藏，**没有纯改名入口**；改名只发生在导出确认那一步（用户 2026-11-12 拍板；文件 chip 不加右键/铅笔入口）。
- 空 / 纯空白提交 = **保持原名**（不清空、不报错）；允许重名（身份靠 `tab:N` / `doc:N`）。

### 5. 清洗与长度（`shared/doc-name.ts`，单一来源）

- `sanitizeDocName`：`trim` → 去控制字符 → 文件系统非法字符 `/ \ : * ? " < > |` 换成 `-` → 去掉末尾 `.json` → 去末尾的点/空格 → 截到 **120 个码点**（码点安全，不砍代理对）。
- 导出文件名总长 ≤120（先给后缀与 `.json` 留位再截基名，文档导出与表达式结果导出共用同一套）；基名清洗后为空时用 `untitled` 兜底（与导入兜底 `untitled.json` 同名；正常路径不可达，纯防御）。不做后缀智能去重（用户输入 `a-edited` 且文档有修改 → `a-edited-edited.json`，不猜意图）。
- 不处理 macOS/Windows 文件名保留字（CON/PRN 等），交给系统对话框自己拒绝。

### 6. 实现位置：不新增协议、Worker 零改动

- `src/shared/doc-name.ts`（**新建**，纯函数：`sanitizeDocName` / `exportFileName` / `baseNameFromExport` / `renameFromExport` / `displayTitle` + `DOC_NAME_MAX`）。
- `view/tab-strip.ts`：只做 DOM——双击 / F2 进入编辑、输入框替换标题、提交/取消回调 `onRename`；语义全在 app。
- `viewmodel/workspace-state.ts`：`TabView` 增加 `originalName`（原名只读给悬停 title 用）；改名走既有 `update(id, {name})`，**不新增方法**。
- `app/main.ts`：`applyDocRename`（清洗 + 写显示名）、`applyExportName`（反推联动）、`exportDoc`（系统另存为 + 回落）、显示层改读活名字（文件 chip / 导入层覆盖警示 / 导出默认名 / 悬停 title）。
- Worker / `protocol` **零改动**；`meta.name` 仍只读（页面侧不改 Worker 副本）。

### 7. 预算

`page.js` 首屏 gz 预算 **48 → 50KB**（用户 2026-11-12 拍板；实测 **48.8KB**，+1.2，归因见「验收结果」）。`page.css` / `worker.js` / 懒加载 chunk 不变。

## 实现期决定（code review 收口，2026-11-12）

1. **双击非活动标签改名走第二击（`event.detail === 2`）**，不只依赖 `dblclick`：首击会切标签
   并整条重绘，第一次点击的节点被替换，浏览器未必把 `dblclick` 派发到新标题上；冒烟补了
   「双击非活动标签 → 激活 + 进编辑」用例。
2. **失焦提交不把焦点抢回标签**（Enter 提交才 `focusTab`）：否则用户点别处会先被改名框把焦点
   拽回来。
3. **表达式结果导出名与文档导出共用长度上限**（`exprExportFileName` 复用 `joinFileName`），
   避免 120 码点基名 + `-expr-N.json` 溢出；`sanitizeDocName` 在 `.json` 前后各去一次末尾
   点/空格（`a .json` → `a`）。
4. **dev hook `exportFileName` / `exportLastAction.name` 统一到真实导出预填名**：修既存分叉
   （旧实现在表达式视图下 hook 报文档名、下载名却是 `-expr-N.json`），与 ADR-0018 §4 对齐。
5. **空基名兜底 `untitled`**：见 §5；仅在防御路径触发。

## 被否决的替代

| 方案 | 否决理由 |
|---|---|
| 只改标签显示名、导出名不变 | 用户要的是「标签名 / 文件名」两处一起改，拆开会出现两个名字的困惑 |
| 显示名与导出基名两套独立可编辑名 | 多一个字段与一处编辑入口；「标签显示 订单、导出 orders-2024」目前无真实诉求 |
| 自制确认框（基名可编辑 + 后缀只读 + 实时预览） | 用户 2026-11-12 追加「可以设置导出位置吗」→ 系统「另存为」一个框同时解决名字 / 位置 / 覆盖确认，少一套自制 UI（原 Q8 的「后缀只读」作废，改为后缀默认预填、用户可覆盖） |
| 文件 chip 右键菜单 / 悬停铅笔（单文档改名入口） | 用户拍板：单文档没有标签改名入口，只经导出改名流程 |
| `chrome.downloads` + `saveAs: true` | 需要新增 `downloads` 权限（安装时多一条「管理你的下载」警告），违反零权限纪律 |
| 记住上次导出目录（目录句柄） | 需要 `showDirectoryPicker` + IndexedDB 持久化句柄 + 每会话权限再确认；单开票再议 |
| 改名写 `tjv.ui.v1` / `tjv.settings.v1` | 标签本就不跨刷新恢复，单独持久化名字无处可挂；#35 最近文档一起做才有意义 |
| 用 `window.prompt` 或浏览器原生改名 | 无位置选择、样式不可控、扩展页里 a11y/焦点难收口 |

## 验收结果（本机实测 2026-11-12）

- `npm run check`：tsc + **单测 979 → 1003（38 文件）** 全绿（新增 `tests/unit/shared/doc-name.test.ts` 21 条：清洗 / 末尾点空格 / 后缀顺序 / 表达式导出名与 120 上限 / 反推 / 往返 / 原名 title；`workspace-state` +3：改名只动显示名、替换导入重置、不影响其它标签）。
- **15 套真机冒烟串行全绿**：`smoke-workspace` **50 → 56/56**（+6：双击出输入框且全选/禁拖拽、Esc 取消、F2 入口、Enter 提交后标签+chip 同步且 title 带原名、空白提交保持原名、双击非活动标签也能进编辑）、`smoke-export` **22 → 27/27**（+5：另存为桩预填 `sample.json`、写入文本逐字等于导出文本、桩返回改名后 chip/标签同步、取消另存为零副作用、策略拦截（`NotAllowedError`）回落普通下载）；`smoke-repair` 14/14 及其余 12 套计数不变。
- **体积**（minify gz）：`page.js` 47.6 → **48.8KB**（预算 **48 → 50** 经用户 2026-11-12 拍板；+1.2 归因：标签就地改名 DOM/焦点 + 导出系统框/回落 + 清洗反推纯函数 + 原名 title）、`page.css` **8.2**（+0.0：改名输入框样式）、`worker.js` **63.3** 不变、懒加载 chunk 合计 **145.6**（预算 146）不变。
- 截图：`.spike/smoke/workspace-rename.png`（深色，编辑中）、`workspace-rename-light.png`（亮色，提交后）。
- **真机系统对话框**：headless 里只能证明 API 在扩展页暴露且可调用（`typeof showSaveFilePicker === 'function'`，调用返回 `AbortError`，无原生对话框）；**2026-11-12 用户在真机扩展实测导出：系统「另存为」框正常弹出、写入成功、导出正常**（本 ADR 唯一需人工确认的项已闭环）。

## 已知差距 / 本轮不做

- **后缀可被用户覆盖**：系统框里删掉 `-edited` 就是删掉（不再强制），默认仍会预填。
- **无 FSA / API 可用但被策略拒绝时回落**普通下载：没有确认框，直接用当前名字落默认下载目录（冒烟用桩覆盖了 `NotAllowedError` 分支）。
- **反推是启发式**：只按「本次确实加过」的后缀剥一层；用户手写成与后缀同名的基名（如 `a-edited-edited.json`）属极端输入，不保证剥对。
- **改名不持久化**（刷新即失）；`#35 最近文档` 落地时再决定是否随最近文档恢复显示名。
- **单文档没有纯改名入口**：想改显示名必须先真导出一次（用户明确接受）。
- **系统框内的文件名合法性交给操作系统**；扩展侧只做 `sanitizeDocName`（存量名 / 内联改名路径）。
- `docs/design/direction.md` §11 的「文件名 + ×」口径不变（标签条仍是 32px 最简条）；改名态输入框沿用既有 token，不新增颜色。

## 决策来源（2026-11-12 会话，grill 逐轮）

- Q1 影响面 = **一个名字覆盖显示 + 导出基名**，每标签独立；Q3 编辑形态 = 就地内联；Q4 持久化 = 会话内；Q5/Q12 清洗与兜底（trim / 非法字符 / 末尾 `.json` / 120 码点 / 允许重名 / 改名不算修改）。
- Q6/Q13 预算 = 48 → 50（实测记账）；Q14 = **系统「另存为」替代自制确认框**；Q15 = 保存后按最终文件名反推更新标签、取消零副作用、表达式结果导出一次性不回写。
- Q2 原案（文件 chip 右键改名给单文档用）与 Q8 原案（后缀只读 + 预览）均被用户 2026-11-12 的「单标签只经导出改名」「可以设置导出位置吗」两次追加推翻，以本节为准。
