- 相关：#1（地图）、ADR-0001（worker 常驻 + 行窗口）、ADR-0002（值图 / 行模型）、ADR-0005（构建与预算）、ADR-0008（分层与 seam）、ADR-0018（补全数据源 = 文档概要）、ADR-0022 §8（预算记账纪律）

## 背景

### 现状（2026-11-13 实测，HEAD `6e82701`）

- **补全只吃根级字段**：`complete` 命令在 worker 里每次从文档**根值**取顶层 key / kind，再拼全局白名单 + 数组/字符串方法字典（`src/core/doc-service.ts:988`、`src/core/expression/complete.ts`）。`items.` 这类成员访问只给**数组方法并集**，拿不到元素真实字段。
- **`DocumentProfile` 形状存在但无人使用**：`src/protocol/types.ts:86` = `{ sampleKeys, maxDepth, nodeCount }`；`profile` 命令在 worker 里与 `getTrail` 一起抛 `NOT_IMPLEMENTED`（`src/core/doc-service.ts:265`）。
- **右栏「文档概要」是纯展示占位符**：`src/app/page.html:180` 写死「导入后采样」，**没有接线**，功能实际不存在。
- **精确节点数已有口径**：`countDocumentNodes()`（`src/core/expression/engine.ts`），`doc-service.docNodeCount` 惰性计算并按 `(rootId, docRevision)` 缓存；`{a:1}` = 2、`[1,2,3]` = 4。3M 节点估 30–60ms（ADR-0018 §3 已知差距）。
- **补全是异步 worker 往返**：CM6 `CompletionSource` 在 `.` 后自动弹（`src/view/panels/expression-editor.ts:400`），每次 keystroke 都可能触发一次 `complete`；因此 profile 必须在 worker 侧**缓存就绪后 O(1) 查询**，不能每次补全都遍历。
- **体积**：`page.js` **50.3KB gz / 预算 51（余 0.7）**、懒加载 **145.6/146（余 0.4）**、`worker.js` 64.4（无硬预算）。
- **右栏可见性**：右栏（选中节点 / JSON 地图 / 文档概要）默认展开，可折叠；`railCollapsed` 进 `tjv.settings.v1`。

### 产品目标（#28）

1. 右栏「文档概要」显示真实采样数据（节点数、最大深度、顶层/元素字段与频率）；
2. 表达式补全能提示**文档里真实存在的字段**（`items.` → 元素字段 `name/price/…`），而不是只有方法字典；
3. 一份 profile **两处消费**（右栏 + 补全），不做两套 derive。

## 决策

### 1. 范围与切片：一张实现票（#43），两个 slice

- Slice A（worker）：采样纯函数 + `profile` 命令实装 + `DocumentProfile` 重设计 + `complete` 消费 profile。
- Slice B（page）：右栏「文档概要」模块渲染 + 按需触发/失效接线。
- 补全接线是「消费 profile」的薄层，与采样同票同 ADR，避免 `DocumentProfile` / `complete` 契约在两票之间反复漂移。ADR 本页即为设计记录（不另开票）。

### 2. 触发时机：**首次需要时按需采样**，不在导入路径上

- 触发点：**右栏「文档概要」可见时**（导入完成/切标签后若右栏未折叠，在第一帧渲染完成之后用 `requestIdleCallback`（无则 `setTimeout 0`）调度一次）**或首次进入表达式模式**时（二者任一先到就采）。
- **导入路径零新增成本**：`load` 回包处理与首帧渲染完成之后才调度，绝不阻塞导入首帧。
- profile 未就绪期间补全退化到现有静态候选（根字段 + 白名单），就绪后自动恢复；右栏显示「采样中…」。
- **不做**：导入后无条件自动采样（会和首帧/滚动抢同一 worker 线程）、每 keystroke 重采。

### 3. 采样形态：**两遍**同步遍历（计数+深度一遍、字段收集一遍）+ 一次性缓存

- 单一纯函数 `buildDocumentProfile(value): DocumentProfile`（新模块 `src/core/profile.ts`，worker 侧），**两遍**遍历（设计期探针实测：计数+深度合并单遍 59.4ms vs 分开 64.1ms；第二遍有界收集仅 1–2.5ms，总成本 ≈61ms @50MB）：
  - **第 1 遍（无界）**：显式栈迭代遍历整图，产出精确 `nodeCount`（口径 = `countDocumentNodes`：`{a:1}`=2、`[1,2,3]`=4）与 `maxDepth`（根 = 1）；
  - **第 2 遍（有界）**：再遍历一次做字段/路径样本收集——节点预算见 §4；**只有当 `nodeCount > 50,000` 时才对数组取样 N=32**，小文档（≤50k 节点）**不做数组取样、全量收集**（否则「小文档全量」的承诺与「数组截断」自相矛盾）。
  - 两遍都**显式栈迭代**（禁用递归：ADR-0020 已有 100 万层深嵌套样本，递归会爆栈）。
- 为什么不是单遍：数组是否截断取决于 `nodeCount`，而 nodeCount 必须先走完整图才能知道（鸡生蛋）；两遍的额外成本只有第二遍的 1–2.5ms（探针实测），换来语义清晰。
- **同步、不分片**：在用户主动进入右栏/表达式模式时触发，worker 内两遍都是同步的；不引入分片调度。**若实测 50MB > 100ms 再评估分片**，数字记入验收。
- `doc-service.profile(rootId)`：只接受**文档根**（与 `complete` 同口径；`expr:N` 根 → `BAD_COMMAND`）；结果按 `(rootId, docRevision)` 缓存；**顺手回填 `nodeCountCache`**，让表达式首次求值不再重复遍历（一次采样两处用）。

### 4. 字段收集算法与硬上限（确定性优先）

- **分档**（沿用 #3 §5.1 建议）：
  - 文档节点数 ≤ **50,000** → 第 2 遍字段收集覆盖**全部节点**、数组**不截断**；
  - > 50,000 → 第 2 遍只覆盖「先序遍历的**前 50,000 个节点**」，且**每个数组只取前 N = 32 个元素**参与字段收集（第 1 遍计数仍遍历全部元素）。
- **上限**：路径条目 ≤ **2,000**、字段条目总数 ≤ **20,000**（**按去重后的 `(路径, 字段名)` 条目计**；`freq` 累加不消耗条目）；超限停止收集**新**条目并置 `truncated = true`（节点计数不受影响）。**探针校准**：hotel 形 50MB 文档若按「原始字段出现次数」计已达 19,628/20,000（98%，再取样就误截断），按去重条目仅 **625**（3%）——所以上限必须按去重条目口径。
- **覆盖标记**：`sampled = sampledNodes < nodeCount`（存在未参与字段收集的节点）；`truncated` 只表示**上限**被撞到。小文档全量收集时两者都为 `false`。
- **频率口径**：`freq` = 同一路径模板下「采样到的容器实例中含该成员的个数」——对象路径通常 1；数组路径 = 含该键的**取样元素个数**（≤32，或 >50k 档下按上述预算）。
- **路径模板**：从根的**键路径**，**数组下标不参与**（`$.items[3].room.price` → `['items','room','price']`）；根 = `[]`。数组容器的样本 `kind = 'array'`、`members` = 元素对象的并集字段（按 `freq` 累计）；元素内对象再向下按「数组路径 + 键」继续建样本。
- **类型归一**：同名字段在样本中出现多种类型 → `kind = 'mixed'`。
- **排序（确定性）**：`members` 按 `freq` 降序、同频按**首次出现序**；采样结果对同一文档**完全确定**（无线程/哈希序依赖）。
- **深度口径**：根值 = 第 **1** 层；`{a:1}` → `maxDepth = 2`（与 `nodeCount = 2` 同口径，单测钉住）。
- 阈值/N/上限是**常量**，不放进设置面板（设置仍是 13 行）；以本 ADR 记录，实测后校准。

### 5. 协议契约（重设计 `DocumentProfile`，无兼容包袱）

现形状只有 `sampleKeys` 且无消费者，直接重设计（`src/protocol/types.ts`）：

```ts
/** 字段统计项（#28 / ADR-0025） */
export interface FieldStat {
  name: string;
  /** 该路径容器实例中含此成员的个数（对象路径通常 1；数组路径 = 取样元素数） */
  freq: number;
  /** 多类型混用 → 'mixed' */
  kind: JsonKind | 'mixed';
}

/** 路径样本：根 → 容器的键路径（数组下标不参与，根 = []）及其成员字段 */
export interface PathSample {
  segments: string[];
  kind: 'object' | 'array';
  /** 采样到的该路径容器实例数（对象路径通常 1；数组路径 = 取样元素个数） */
  samples: number;
  members: FieldStat[];   // freq 降序、同频首次出现序
}

export interface DocumentProfile {
  rootKind: JsonKind;
  /** 精确节点数（口径 = countDocumentNodes） */
  nodeCount: number;
  /** 最大嵌套深度（根 = 1） */
  maxDepth: number;
  /** 字段收集是否只覆盖了一部分节点（大文档 / 上限） */
  sampled: boolean;
  /** 实际参与字段收集的节点数 */
  sampledNodes: number;
  /** 路径 / 字段条目是否被上限截断 */
  truncated: boolean;
  /** 至少一条：根（segments = []）；按路径首次出现序 */
  paths: PathSample[];
}
```

- `profile` 命令（已存在，`{ t:'profile'; rootId }`）回包即此结构；`complete` 命令**签名不变**（worker 内部查缓存 profile 拼补全上下文，不把 profile 发到页面）。
- `CompleteReply` / `ExprCompletion` 形状不变。

### 6. 补全能力边界：任意深「纯键链」，不做部分求值

- 接收者解析（v1 仅文档路径链；**回调参数绑定见「修订（2026-11-13 晚）」**）：把 `X.` / `X?.` 的 `X` 解析为**键链**——仅允许 `$`、标识符、`.`、`?.`（如 `items`、`data.items`、`$.data.items`）；链去 `$` 后作为 `segments` 在 profile.paths 中精确匹配。
- 命中 → 给该路径的 `members`（`detail` 固定格式：`${kind} · 采样 ${freq}/${samples}`，`kind` 为 `mixed` 时用「混合」）。**数组路径额外追加数组/字符串方法并集 + `length`**（这些方法对数组元素字段补全同样有效，且标量数组命中时 members 为空、不追加就会得到空候选 = 退化成"没提示"；对象路径只给成员字段）；未命中 / profile 未就绪 → **退化**为现有行为（数组/字符串方法并集 + `length`）。
- 根字段（`$` / 裸标识符 / `$.`）保持现有 `detail` 格式 `根字段 · <kind>`（`main.ts` 依赖它生成动态示例，勿改）。
- 根为数组时：`$.` 给**元素字段**样本（`detail` 同上），不再只给全局名。
- **明确不做**：下标（`items[0].`）、函数调用/方法调用结果、运算结果、括号/字面量后的成员补全——需要部分求值，违反「不为补全执行用户表达式」的安全/成本红线（#3 §5.1）。写进非目标。
- 表达式结果根（`expr:N`）不做 profile：`profile` / 字段补全只对文档根。

### 7. 右栏「文档概要」UI：最小版 + 体积门槛

- 替换 `src/app/page.html:180` 的占位符为真实模块，内容：
  - 元信息行：`节点数 · 最大深度 · 采样状态`（`sampled` 时显示「已采样 N 个节点」；`truncated` 时显示「已截断」）；
  - **根字段列表**：名称 + 类型 + 频率（`freq > 1` 才显示 `×N`；根为数组则标题为「元素字段」）；
  - 空态：「未打开文档」；根为标量：「无可统计的字段」；采样中：「采样中…」；文档已修改：「文档已修改，概要待更新」。
- 复用现有 `.module` / `.module__head` / `.placeholder` 样式与 token，不新增颜色 token；新样式落 `src/view/panels/profile-panel.css`（由 `main.ts` import）。
- **体积门槛（照 ADR-0022 §8）**：`page.js` 余量只有 0.7KB。实现完成先 `node build.mjs --analyze` 实测；**若超 51 必须停下来带实测数字问用户**（预计 51 → 52），不预先占额度、不静默豁免。

### 8. 失效策略与边界

- **失效**：缓存键 `(rootId, docRevision)`；文档编辑推进 `docRevision` → 右栏清空并显示「文档已修改，概要待更新」，**不自动重采**（不在编辑 Apply 路径上加遍历）；下次右栏可见/进表达式模式时按需重采。
- **不持久化**：profile 是标签会话态，换文档 / 关标签 / 刷新即丢（与展开集合同类）；不写 `tjv.settings.v1`。
- **关根**：`closeRoot` 清缓存条目（与 `nodeCountCache` 同处清理）。
- 边界：plain / 截断修复文档照常采样（采样值图，不看源文本）；空文档/根标量 → `paths = [{ segments: [], kind: 'object', samples: 1, members: [] }]` 之类合法空结果（具体形状单测钉住）。

### 9. 验收口径与性能门槛

- **单测**：采样纯函数（阈值分支 / 数组取样 32 / 频率排序 / 首次出现稳定序 / 类型混用 / 深嵌套不爆栈 / 上限截断 / 确定性 / 节点数口径）；补全链解析（`items.` / `data.items.` / `$.a.b.` / 未命中退化 / 根数组元素字段）；`doc-service.profile` 缓存与失效。
- **契约**：`profile` InProcess/Worker 双适配器 + 表达式根 `BAD_COMMAND`；`complete` 非回归。
- **冒烟**：补全列表含真实元素字段；右栏占位符被真实数据替换（节点数/字段名可见）；10MB/50MB 采样耗时实测与 0 长任务（阈值：**50MB 采样 ≤100ms**，一次性、按需、worker 内；实测数字记 ADR 验收）。
- **全套**：16 套冒烟串行全绿 + `node build.mjs --analyze` 体积如实记录 + 深/亮截图 + 文档同步（本 ADR、`CONTEXT.md`、`docs/design/direction.md`、架构 README §11 新 slice **6.29**、`seams.md` 命令/缓存表）。

## 被否决的替代

| 方案 | 否决理由 |
|---|---|
| 导入成功后无条件自动采样 | 与首帧/滚动抢同一 worker 线程；50MB 导入后立刻遍历会拖慢用户第一次操作 |
| 每次 `complete` 现算 profile | 每 keystroke 一次遍历，成本不可接受；补全必须 O(1) 命中缓存 |
| 用采样估算节点数（不精确） | 右栏数字不可信；全量计数本来就要走一遍，估算省不掉遍历 |
| 分片采样（4–8ms/片、片间让出） | 初版复杂度高；单次遍历在上限内成本可控，实测超 100ms 再引入 |
| 运行期反射 / 部分求值取字段 | 违反安全红线（不执行用户表达式）；#3 §5.1 明确否决 |
| 字段表按全文档唯一路径存 | 3M 节点 × 路径会爆内存（与 ADR-0020 否决全量 path 索引同理）；用路径模板 + 上限 |
| 补全支持下标 / 调用结果（`items[0].`） | 需要部分求值，成本与安全边界都不划算；写进非目标 |
| 另开独立「文档概要」票 | 补全只是消费 profile，拆票会让契约反复漂移；一张票两 slice |

## 验收（待实现实测，见实现票 #43）

### 设计期探针（2026-11-13，Node v24 本机；非 Chrome worker，量级 ±10%）

样本：49.41MB / **3,090,013 节点** / maxDepth 5（hotel 形：root → `hotel_list[5000]` × 618 节点 + meta）；对照 9.88MB / 618,013 节点。

| 阶段 | 50MB 中位 | 10MB 中位 |
|---|---|---|
| `JSON.parse`（导入时已付，不计入 profile） | 266.1ms | 49.9ms |
| 精确 `countDocumentNodes`（现仓库函数） | 63.7ms（冷 84.8ms） | 11.8ms |
| 计数 + maxDepth 合并单遍 | **59.4ms** | 13.0ms |
| 有界字段收集（第 2 遍，数组取样 32） | **1–2.5ms**（热 0.93ms） | 1.4ms（热 0.93ms） |
| 上限撞顶最坏（node 200k / path 2k / field 20k） | ≈15ms | ≈15ms |

- **确定性**：同文档 3 次同进程 + 4 个进程复跑 digest 完全一致。
- 结论：两遍合计 **≈61–62ms（冷 ≈85–88ms）@50MB**，在「50MB ≤100ms」门槛内；字段收集成本可忽略（真正大头是导入时已付的 `JSON.parse` 266ms）。撞顶由**数组取样 N=32** 主导（把 3.09M 节点压到收集 19.8k 节点），三条硬上限是安全阀。

## 修订（2026-11-13 晚）：回调参数绑定（#44，用户追问）

用户追问「`items` 是对象数组，写 `items.map(item => item.)` 没有提示字段，符合预期吗」——原设计（§6）只解析**文档路径链**，回调参数不在 `paths` 里，所以不提示（ADR 记录的非目标）。用户拍板：做**单层**回调参数绑定，且支持**对象字面量体**（`map(item => ({a: item.a, b: item.b}))`）——即绑定是**作用域级**的，不是只紧跟 `=>`。

### 决策

1. **语义**：`<纯键链>.map(param => …param. …)` 中 `param` = 该路径的数组元素；补全候选 = 该路径 `PathSample.members`（元素字段），detail 沿用采样格式 `${kind} · 采样 ${freq}/${samples}`；**不追加**数组方法（元素是对象，不是数组）。
2. **作用域级**：光标位于该回调 body 内任意位置（紧跟 `=>`、对象字面量 `({ …: param. })`、多行 body）都生效；`param?.` 变体、以及**裸前缀**（`map(x => x`，无点）同样按元素字段提示；只认**独立出现**的 `param`（`other.param.` 不算）。
3. **方法白名单**（单参数回调 = 元素）：`map / filter / find / findIndex / some / every`——**从 `whitelist.ELEMENT_CALLBACK_METHODS` 取**（`ARRAY_METHODS` 的子集，单测钉住），不含引擎不支持的 `forEach` / `flatMap` 与累加器语义的 `reduce`（「提示什么 == 允许调什么」红线）；接收者支持纯键链（`items` / `$.data.items` / `?.` 链）与**根数组 `$`**（`$.map(x => x.`）；参数写法支持 `param =>` 与 `(param) =>`（Prettier 默认）。
4. **非目标 / 不解析**：`reduce` / `sort`（多参数、语义不是元素）；嵌套回调链（`x => x.tags.map(t => t.`，需要多层绑定）；解构参数（`({name}) =>`）。这些退化为原行为。**回调闭合校验已实现**：`items.map(x => x.a); x.` 的 `x.` 不再绑定（与未绑定标识符同行为）。
5. **实现**（worker 侧，`core/expression/complete.ts`）：`elementCallbackBind()`（正则按白名单动态拼接、函数内构造，支持 `(param) =>`）扫光标前文本；`callbackParamSample()` 只取**独立出现**（前一字符不是 `.`）、**早于使用处**、且 `callStillOpen()`（配对括号/字符串扫描）判定**光标时仍未闭合**的最近绑定；解析路径链（`$` → 根样本）→ `memberFieldCompletions()` 给字段（与数组路径补全共用同一成员映射）。页面零改动、`page.js` 零增量。**审查收口**：方法表从 `whitelist` 派生、闭合校验、链尾同名（`other.param.`）排除。

### 验收（2026-11-13 晚，实现票 #44）

- **单测 1228 → 1241**（+13：作用域级 / 对象字面量体 / 多行 body / 各回调方法 / `?.` 链与 `x?.` / 裸前缀 / 括号单参 / 根数组 `$.map` / 回调闭合不绑定 / 链尾同名不绑定 / 嵌套不解析 / `reduce`·`sort` 不绑定 / 未绑定不回归 / 白名单子集不漂移）。
- **冒烟 `smoke-expression` 55 → 57/57**：`data.items.map(x => x.` 与 `data.items.map(x => ({ n: x.` 均给 `id/name/price`，且不混入全局名。
- **体积**：`page.js` **51.2 不变**（预算 52）、`worker.js` 65.8 → **66.2**（+0.4，无硬预算）、`page.css` 8.3 / 懒加载 145.6 不变。
- 架构 README §11 新增 **6.30** 行。

### 被否决的替代

| 方案 | 否决理由 |
|---|---|
| 不做（保持 §6 非目标） | 这是最常见写法，`items.` 有提示而 `item.` 没有的落差太刺眼 |
| 只支持紧跟 `=>` 的位置 | 对象字面量/多行 body 是主流写法，只支持一种位置反而更奇怪 |
| 支持嵌套回调链 / 解构 | 需要作用域链与模式解构分析，复杂度不成比例（单层已覆盖绝大多数真实用法） |
| 执行部分表达式求值取字段 | 违反「不为补全执行用户表达式」红线（#3 §5.1） |

### 已知差距（修订）

- 纯**文本**绑定、不做变量作用域分析（如 `const y = x; y.` 不跟随）；括号/字符串配对是轻量扫描（表达式子集无注释/正则字面量，边界可控）。
- 嵌套回调链（`x => x.tags.map(t => t.`）、解构参数（`({ name }) => name.`）、`reduce` 累加器不做绑定。

## 已知差距 / 本轮不做

- 字段频率是**采样值**，不做统计置信区间；`truncated` 只给"已截断"标记，不给缺了多少。
- 数组元素形状异构时给 **union + 频率排序**，不聚类、不区分「主流形状 vs 离群形状」。
- 不做按文档编辑**增量**更新 profile（编辑 → 整体失效 → 按需重采）。
- 不做 profile 持久化 / 跨会话恢复；不做用户可配阈值。
- 补全不做「字段 → 值示例」预览、不做语义类型推断（只做样本形状）。
- 右栏不显示每个路径的样本（只显示根/元素字段列表），更深的路径样本只服务补全。
- 第 1 遍全量计数在 50MB 上产生 ≈50MB 瞬时垃圾（探针实测，GC 后保留 0）；Node 与 Chrome MV3 worker 的绝对值有差异（探针 ±10% 级），以 Chrome 冒烟实测为准。

## 决策来源（2026-11-13 会话，grill 一轮 9 问，全部按推荐）

1. 范围：一票两 slice + 本 ADR（不拆票）。
2. 触发：首次需要时按需（右栏可见 / 首次进表达式模式），导入路径零成本。
3. 形态：同步**两遍**遍历（计数+深度一遍 / 有界字段收集一遍）+ 精确 nodeCount + 回填 nodeCountCache + 一次性缓存，不分片（设计期探针实测 50MB ≈61ms）。
4. 算法：保留 50k 全量阈值、数组每层 N=32、路径 ≤2k / 字段 ≤2 万上限（字段按**去重条目**计，探针校准）、确定性排序。
5. 契约：重设计 `DocumentProfile`（rootKind / nodeCount / maxDepth / sampled / sampledNodes / truncated / paths），`complete` 签名不变。
6. 补全边界：任意深纯键链命中 `paths` 给字段，未命中退化方法并集；不支持下标/调用/运算；表达式根不采样。
7. UI：最小版（元信息 + 根字段列表 + 四类空态），复用现有样式；超 51 带数字问用户。
8. 失效：docRevision 惰性失效 + 按需重采，不自动重采、不持久化。
9. 验收：单测 + 契约 + 冒烟（补全真实字段 / 右栏真实数据 / 50MB ≤100ms 且 0 长任务）+ 16 套 + analyze + 截图 + 文档。
