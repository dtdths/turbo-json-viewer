# 临时子树 JSON 编辑 — v1 spec

> 关联：#16、ADR-0006。目标：在**不修改原文件、不持久化**的前提下，支持当前会话内的 mock 数据编辑。
> 编辑的唯一入口 = 选中节点 → 编辑该节点 JSON → Apply → 整段替换回 Worker 值图。

## 1. 目标 / 非目标

**目标**
- 改标量、增删字段、增删子结构、改键名——全部通过编辑该节点的 JSON 文本完成。
- 原文件/源文本不写回；关闭页面即丢弃；导出才产生 `-edited` 文件。
- 不改「文档常驻 Worker + 行窗口」架构：不重解析整份文档、不重建全树、全文不进 DOM。

**非目标**
- 源文本/全文编辑器（CM6 仅用于子树编辑 + 表达式输入）。
- 拖拽移动/重排、批量/多选编辑、多文档合并。
- 保留「替换后仍然存在的子路径」的展开状态（S2，v1.1）。
- 结构化「新增/删除/改名」专用菜单（由 JSON 文本编辑覆盖）。

## 2. 交互

- **入口**：行右键菜单「编辑此节点 JSON」；双击行/值同样打开；选中行按 `F2`/`Enter`。
- **弹层**：
  - 顶部：路径面包屑 + 节点类型（object/array/string/number/boolean/null）+ 文本大小；
  - 编辑器：CM6 + `@codemirror/lang-json`（语法高亮 + JSON lint），内容 = `JSON.stringify(当前值, null, 2)`；
  - 底部：`Apply`（Cmd/Ctrl+Enter）、`Cancel`（Esc）、`恢复当前值`（回到打开时的值，不是原文件）；
  - JSON 非法时行内 lint + Apply 禁用；不产生修改。
- **Apply 后**：
  - 保留被替换节点**自身**的展开状态（S1）：原来展开就仍展开，其直接子节点默认折叠；原来折叠就仍折叠；
  - 滚动到该节点并短暂高亮；重取受影响行窗口；顶部修改计数 +1。
  - 若替换的是根节点：根保持展开、顶层字段可见、其下全部折叠。

## 3. 数据流

```
打开编辑：
  main → { t:'getNodeJson', rootId, rootVersion, path }
  worker → { text, bytes, nodes }            // JSON.stringify(value, null, 2)
  bytes > EDITOR_MAX_BYTES(5MB) → { error:'TOO_LARGE', bytes } → UI 只读提示

Apply：
  main → { t:'replaceNode', rootId, rootVersion, path, jsonText }
  worker → JSON.parse(jsonText)（≤5MB）
        → 替换该路径的值 → rootVersion++
        → 行模型增量更新 → { totalRows, changedRow, changedPath }
  main → 重取窗口 + 高亮 + 更新修改计数/撤销栈
  解析失败 → { error:'PARSE', message, line, column }；不修改
```

- 文本未变化（与打开时文本完全相同）→ no-op，不推进版本。
- 打开编辑时生成的文本是**当前值图的规范 JSON**，不是源文本切片；因此原格式/大数原文不会保留（见 §7）。

## 4. 行模型更新（replaceNode）

设被替换路径为 `p`，新值 `v'`：

1. **结构**：父容器的子项位置不变（替换的是第 i 个成员/元素），父容器 Fenwick 只需**点更新**该子项的可见行数（O(log n)）；祖先可见计数沿链更新。
2. **被替换节点**：
   - 若 `v'` 是标量：该行变为标量行（无子项）。
   - 若 `v'` 是容器且原节点处于展开态（S1）：为该节点新建 Fenwick（O(子项数)），可见行数 = 1 + 子项数（子项默认折叠）。
   - 若原来折叠：保持折叠，可见行数 = 1。
3. **展开集合**：删除 `p` 之下所有展开路径；`p` 自身按 S1 保留/清除；新子节点不展开。
4. **选中/锚点**：选中替换后的节点；若替换发生在视口上方，按行高调整 `scrollTop`，保持视口内容不跳。
5. **版本**：`rootVersion++`；主线程丢弃旧窗口回包（`STALE_ROOT`）。
6. **根节点替换**：重建根行模型；根展开、顶层字段可见、子级折叠；`totalRows = 1 + 顶层字段数`。

> 结构变化只在显式 Apply 时发生，成本可接受；大容器（如 10 万项）重建 Fenwick 约数 ms～十几 ms，需在实现中用真实样本回归。

## 5. 临时语义

- **修改计数**：工具栏「已临时修改 N 处」；N = 当前生效的编辑步数（撤销后减少）。
- **撤销/重做**：栈深度 100；每次 mutation 记录 `{ path, oldValue, newValue }`（undo 用 oldValue 反向 replace，redo 用 newValue）。
- **重置全部**：丢弃所有编辑，用源文本重新 `JSON.parse` 得到原文档；清空栈/计数；展开集合按路径裁剪到仍存在的节点。
- **关闭/卸载**：有修改时 `beforeunload` 提示「临时修改未导出」；不持久化任何文档内容。
- **导出**：Worker `JSON.stringify(doc, null, indent)` → 下载 `原名-edited.json`；这是唯一落盘动作；原文件不动。

## 6. 一致性

| 能力 | 编辑后的行为 |
|---|---|
| 搜索 | 清空命中并提示「文档已修改，搜索结果已清空」；用户重新搜 |
| 表达式结果根 | 标记 stale（banner「文档已修改，请重新执行表达式」）；用户重跑 |
| 原始文本视图 | 始终显示原始源文本；顶部/视图内标注「原始文件文本，不含临时修改」；v1.1 可提供「按值图重建 pretty」 |
| 复制（子树/路径/原值/键名） | 使用修改后的值图 |
| 导出 | 使用修改后的值图，`-edited` 后缀 |
| 视图状态持久化 | 临时修改不落盘；重新打开同一原文档时恢复的是原文档 + 原视图状态 |
| 复合/表达式结果导出 | 结果根导出使用其当前值（受编辑影响的部分按新值） |

## 7. 守卫与保真

- **编辑器文本阈值 5MB**（根节点同限）；超限只读并提示「请选择更小的子树」。
- **JSON 语法错误**：返回 line/column/message，编辑器内展示，不修改。
- **保真提示**（编辑时展示一次或在帮助中）：
  - number 按 JS double 处理（>2^53 的整数会丢精度）；
  - 对象键序：字符串键保持插入序；整数样式键可能被 JS 重排；
  - 重复键在 `JSON.parse` 时后者胜出；
  - 编辑器文本是规范 pretty JSON，不是原始文本。
- **no-op**：文本与打开时完全相同 → 不修改、不推进版本。
- **空对象/数组/null** 合法；根可替换为任意合法 JSON。
- **编辑与其它异步操作互斥**：文档加载中、Apply 中禁用再次 Apply。

## 8. 验收 / 测试

- 编辑标量（四种类型互转）、对象增/删字段、增删子结构、数组增/删元素、改键名 → Apply 后树/行窗口/搜索/复制/导出均反映新值。
- S1：被替换节点保持原展开状态；其子节点折叠；被删子路径的展开状态清理；滚动不跳。
- 根节点 ≤5MB 可编辑；>5MB 只读。
- 非法 JSON：无修改、行列号正确。
- Undo/Redo/Reset；修改计数；关闭提示；导出 `-edited`；原文件字节不变（校验 hash）。
- 搜索清空、表达式 stale banner。
- 原始文本视图 banner。
- 性能：951K 真实样本上打开/Apply 无 >50ms 长任务（大子树另测）；10MB 样本编辑子结构可用。

## 9. 实现备注

- 协议新增两条消息：`getNodeJson` / `replaceNode`（另有 undo/redo/reset 可由主线程重放 mutation 或 Worker 维护快照）。
- 行模型需暴露 `replaceNode(path, value)`：父 Fenwick 点更新、节点 Fenwick 重建（展开时）、祖先计数、展开集合裁剪、锚点换算。
- CM6 包集合：现有最小集 + `@codemirror/lang-json`（+ `@codemirror/lint` 若 lang-json 的 linter 需要）；体积/初始化需实测。
- 弹层里编辑器高度、长字符串折行、横向滚动需样式验证。
