## 1. 两套方向

| | A · Graphite / Indigo | B · Slate / VS Code |
|---|---|---|
| 目录 | `prototype/visual/a/` | `prototype/visual/b/` |
| 气质 | 安静、紧凑、定制感；Linear/Raycast | IDE、结构感、熟悉；VS Code |
| 行高 | 24px | 26px |
| 骨架 | 顶部工具栏 + 树 + 浮层地图 + 状态栏 | 活动栏 + 工具栏 + 标签条 + 面包屑 + 状态栏 |
| 强调色 | 靛蓝 #7C8CFF | 蓝 #4EA1FF |
| 语法色 | 克制冷色 + 青绿/琥珀/紫 | VS Code dark+ 语法色 |
| 地图 | 浮层层级塔 + 兄弟刻度 + 面包屑 | 浮层层级塔 + 兄弟刻度 + 全局位置轨道 |
| 适合 | 长时间看密集 JSON；更轻、更独特 | 习惯 VS Code 的开发者；结构优先 |

两套均覆盖：main / empty / 子树编辑 / 表达式 / 搜索 / 修复态；暗色默认 + 完整亮色；1440×900、1280×720；零依赖、零外链、无 console 错误。

## 2. 评审标准（来自 #6 + 产品约束）

1. 专业、克制，不像模板/现成 IDE 仿品；
2. 深色默认、亮色完整；
3. 树视图可读性：键/值/类型、缩进、折叠、计数、长值；
4. 深节点导航：JSON 地图能否一眼看到「在哪一层、上一层是谁、index 多少」；
5. 搜索/表达式/子树编辑的入口与状态是否清晰；
6. 中英双语槽位、a11y（focus/aria/对比度）；
7. 单文档只读工具的契合度（不引入无用的 IDE 复杂度）。

## 4. Lead 建议

**以 A 为基础，吸收 B 的两个细节：**

1. **可选右对齐类型列**（B）：帮助快速扫读 `OBJECT/ARRAY/STRING/...`；默认关闭或仅宽屏显示，避免增加视觉噪声。
2. **搜索结果侧栏的显式结构**（B）：`共 37,189 · 3 / 37,189 · 上一个/下一个`，比 A 的浮层结果栏更适合大命中集。
3. 其余保持 A：24px 行高、靛蓝只标焦点、单层顶部工具栏、右下浮层 JSON 地图。
4. 若你更看重 VS Code 熟悉度，选 B 也成立；但建议去掉“活动栏”或让它默认收起，避免单文档工具显得过重。
