# Turbo JSON Viewer — 视觉方向（v1 定稿：C · 工作台）

> 状态：**Confirmed**（2026-10-28，人类确认 C 方案）
> 定稿内容：**A · Graphite/Indigo 的视觉语言 ＋ B 的活动栏与双侧工作区**
> 高保真原型：`prototype/visual/c/`（实时对比 `prototype/visual/compare.html`；截图 `prototype/visual/shots/c-*.png`）
> A/B 两套原型的评估依据：`docs/design/direction-review.md`；token：`docs/design/tokens.css`（沿用 A，未新增颜色）
> 相关票：#6（视觉方向）、#13（模块 seam，实现时落地结构）

## 1. 结论

**C = A 的皮 + B 的骨架。**

1. **视觉语言全部沿用 A**：Graphite 中性色、靛蓝只标焦点、24px 行高、单层工具栏、语法色只在数据上出现、默认深色 + 完整亮色。
2. **结构吸收 B**：
   - 左侧 **48px 活动栏**：文档树 / 搜索 / 大纲 / 表达式（模式切换，带激活态）；底部 主题 / 设置。
   - 左侧 **320px 面板**：搜索（查询 + 结果 + 过滤）、大纲、设置。
   - 中间 **JSON 视图**：不占满总宽，左右各让出面板；最大宽度 1280px 居中，深层内容横向滚动。
   - 右侧 **300px 工作区**：JSON 地图 + 选中节点 + 文档概要 + 临时修改，整栏可折叠。
3. **顶部工具栏只放文档动作**：品牌、文件 chip、临时修改徽标、导入、导出、右侧栏开关。

**明确不采用**：B 的活动栏 + 标签条 + 面包屑行 + 蓝色状态栏（对单文档只读工具过重，也容易被当成 VS Code 仿品）；A 的右下浮层地图与顶部搜索框（位置让给侧栏）。

一句话：**A 的密度与克制，装进 B 的工作台骨架**——数据始终是主角，两侧面板是可收起的工具，不是常驻的 IDE 结构。

## 2. 命令归属（一个命令只有一个家）

| 位置 | 放什么 | 判断依据 |
|---|---|---|
| **活动栏（左）** | 文档树 · 搜索 · 大纲 · 表达式；底部 主题 · 设置 | 有「当前处于哪个视图」的状态，属于**模式切换**，需要常驻 + 高亮 |
| **工具栏（顶）** | 品牌 · 文件 chip · 修改徽标 · 导入 · 导出 · 右侧栏开关 | **文档级动作**，与当前视图无关，不需要激活态 |
| **状态栏（底）** | 节点数 · 行数 · 大小 · 只读 · 当前路径 · 语言/主题/本地 | 只读信息，不承载操作 |

> 教训：A/B 原型里搜索、表达式、主题、设置在工具栏与活动栏各有一套（B 也有此问题），C 已去重。
> 例外：右侧栏开关在工具栏与右栏头部各一个——折叠后面板头不可见，必须保留工具栏入口才能展开。

## 4. 视觉 token、字体、颜色纪律（沿用 A，不变）

- Token 全量见 `docs/design/tokens.css`（dark 默认 + light 完整覆盖，变量同名）。C 未新增颜色 token，只新增尺寸变量（`--activity-w` / `--left-panel-w` / `--rail-w` / `--tree-max`）。
- 字体：UI `system-ui` 13px；JSON `ui-monospace` 12.5px / 行高 24px；微文本 10–11px。
- 颜色纪律（A 的原文，继续有效）：
  - 靛蓝 `--accent` **只**用于焦点、选中、动作、进度；不用于数据值。
  - 数据颜色只区分 JSON 类型；不给键名/字符串再加装饰色。
  - 搜索命中是唯一暖色（琥珀）；修复/错误用语义色，不与强调色混用。
  - 层级靠背景明度 + 1px 边框，不靠阴影堆叠；阴影只给浮层/弹层。

## 5. 树行与长值（关键约束）

**树行不换行**，这是架构约束而不是审美取舍：

- 行窗口协议按**固定行高**取值、滚动条 = `totalRows × rowH`（ADR-0001）；允许换行即行高可变，需要逐行测量 + 高度前缀和 + 窗口宽度变化时重算——而侧栏开合本身就在改宽度。50MB / 2,958,550 行下不可行。
- 因此：树内单行省略（长值预览已有 620px 上限）；**完整值在右侧「选中节点」面板换行显示**（可滚动）；编辑走子树 JSON 弹层（ADR-0006）。
- 深层嵌套靠：缩进 16/12px 可切、树内横向滚动、JSON 地图与大纲跳转、折叠行预览。

## 7. 双主题

默认 dark；`data-theme="light"` 覆盖同一组变量，不是反色。C 的两侧面板/活动栏全部沿用 A 的 surface token：活动栏与面板同 `--bg-panel`，仅靠 1px `--border` 与树区 `--bg-app/--bg-panel-2` 拉开层级。

## 8. a11y / i18n

- 活动栏按钮：`aria-label` + 激活态需同步 `aria-current`（原型用 class，实现时补）；键盘可达。
- 树：`role=tree/treeitem` + `aria-activedescendant`，行回收不丢焦点。
- 地图：Canvas `aria-hidden` + 文本面包屑 + `aria-live=polite`。
- 侧栏折叠按钮：`aria-expanded` / `aria-pressed`；折叠后仍有工具栏入口。
- 对比度：正文 ≥4.5:1；沿用 A 的暗/亮两组检查。
- 文案中文为主，英文 `_locales` + `aria-label` 槽位。

## 9. 与 A / B 的关系（决策依据）

`direction-review.md` 的评分：A 在专业/克制、密度、独特性、单文档契合领先；B 在 IDE 熟悉度、亮色完成度领先，且提供可竖扫的类型列。人类最终选择 **C = A 的表现层 + B 的结构层**，理由：

1. 要 A 的「数据为主角、界面后退」的气质，不要 B 的 IDE 外壳。
2. 活动栏解决了 A 的一个真实短板：**搜索/表达式/大纲没有稳定的常驻入口**（A 靠顶部按钮 + 浮层）。
3. 左侧搜索面板 + 右侧工作区让「文档视图居中、两侧放工具」成立，长文档导航不再依赖浮层遮挡。
4. 类型列从 B 保留为**可选**（默认关，≥1280px 可在设置开启）；搜索从 A 的右侧栏**迁到左侧**（人类要求）。

被否决：纯 B（活动栏/标签条/面包屑/蓝色状态栏过重、辨识度低）；纯 A（搜索与导航入口弱、两侧空间浪费）。

- 原型交互已可用：活动栏切面板、右栏折叠、主题切换、搜索上下条、地图 Canvas 真实绘制；数据为硬编码演示值。
